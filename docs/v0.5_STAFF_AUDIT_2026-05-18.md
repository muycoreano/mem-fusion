# v0.5 Codebase — Staff Engineering Audit

**Author:** Claude-Engineer (mc-macbookair) · 2026-05-18
**Audience:** mc-macbookpro (architect) for review + decision
**Trigger:** User feedback after watching me ship hacky one-off test scaffolds instead of testing production code paths. Asked for a staff-engineer-level reassessment of code layout for maintainability, composition / separation of concerns, extensibility for connectors, abstraction layers, and practical+performant tradeoffs.

---

## TL;DR

Three patterns I've drifted into that hurt maintainability now and will hurt more as connectors multiply:

1. **`core.py` is a 1007-line god module** doing 10 responsibilities (storage, embedding, hashing, identity, tags, filters, cursors, envelope ingest, Constellation pull primitives, legacy migration). Every feature touches it; every test imports it; every bug hides in it.
2. **`store_memory_from_envelope` in `core.py` knows Slack wire-format details** (`"sha256:" + sha256(content).hexdigest()` integrity check). Connector-layer knowledge bled into storage. The moment a second connector ships with a different integrity scheme, this breaks.
3. **The `Connector` ABC is too thin** for the trajectory ("more connectors coming"). `format_envelope` + `parse_envelope` is fine for prototyping; production needs envelope construction from records, config validation, integrity verification (substrate-aware), and capability metadata.

Plus a meta-issue I created myself: **production code paths and test scaffolds diverge.** My E-D heredocs built envelopes from scratch; production code (0.5.0-016) will build envelopes from stored records via a function that doesn't yet exist. The user correctly called this "hacking together a script."

Recommendation: staged refactor — Stage 1 ships with v0.5 (critical only), Stage 2 fits in v0.5.x, Stage 3 lands alongside v0.6's payload-schema bump.

## Severity-tiered findings

### CRITICAL — block clean v0.5 ship

**C1. `store_memory_from_envelope` has Slack-wire-format knowledge in storage layer.**
Line 451 of `core.py`:
```python
expected_wire = "sha256:" + hashlib.sha256(content.encode("utf-8")).hexdigest()
if wire_hash != expected_wire:
    return {"error": "integrity_failed", ...}
```
The `"sha256:"` prefix and the raw-sha256 algorithm are choices made by the SlackConnector's wire format. If a future GDrive connector uses, say, a Drive checksum or a base64-encoded digest, this function silently rejects it. The integrity check needs to be a Connector method.
- **Fix shape:** add `verify_integrity(envelope) -> tuple[bool, str | None]` to the Connector ABC; have `SlackConnector` implement it with the sha256/`"sha256:"` logic; have `store_memory_from_envelope` accept a `connector_type` argument and dispatch via `get_connector(type).verify_integrity(envelope)`.
- **Cost:** ~30 lines of code (one new method + one call site change + test update).

**C2. No production function exists for "build envelope from a stored record".**
The function 0.5.0-016 push orchestration will need. Today this logic lives in my test heredocs. Until extracted, every test reinvents it; the live Slack post I made tonight had to hand-assemble the envelope, and I hand-stripped the vector at post time — exactly the divergence the user flagged.
- **Fix shape:** add `build_envelope_from_record(record, connector_id) -> Envelope` as a Connector method. SlackConnector's implementation does what I was hand-coding in heredocs: produce the canonical envelope dict from `export_record` output.
- **Cost:** ~40 lines (interface + slack impl + test).

**C3. No `Envelope` schema definition.**
Senders and receivers all access the dict by string keys with `.get(..., default)`. The set of fields is implicit; a new connector author has to read existing connectors to learn what to populate. A typo in `connectore_ids` silently produces "stored without connector_ids" — no error.
- **Fix shape:** `TypedDict` (or `dataclass`) at `src/connectors/envelope.py`. All sites that produce or consume envelopes import it. Optional: a `validate_envelope(env) -> list[str]` function for receivers that don't trust input.
- **Cost:** ~40 lines (TypedDict + 6 call-site updates).

### HIGH — real cost, but works today

**H1. `core.py` is a god module (1007 LOC, 10 responsibilities).**
Symptoms:
- Every PR touches it. Diff conflicts on rebases are common (we just had one).
- Tests import `core` to get at one helper; pulling that helper drags in Qdrant + Ollama + Constellation primitives.
- "Where does X live?" is "core.py, probably" for half the codebase.
- The 1007 LOC includes both architecture-level concerns (envelope ingest, cursor management) and trivial helpers (`iso_now`).
- **Fix shape:** split into `src/core/` submodules along the responsibility groups in the survey table. `from core import *` (or specific names) preserves callers' imports during the transition.
- **Cost:** ~half a day; mechanical, not risky.

**H2. `constellation.py` is similarly monolithic (840 LOC).**
Daemon main + two HTTP handler classes + push/pull orchestration + merge logic all in one file. Same shape problem as core.py.
- **Fix shape:** split into `src/constellation/{daemon,peer_handler,gateway_handler,config}.py`. Already a logical package; just isn't structured as one.
- **Cost:** ~half a day; mechanical.

**H3. Hook scripts are bash with embedded Python heredocs.**
`scripts/prompt_memory_inject.sh` has Python inside a heredoc inside bash with variable substitution. Variable escaping (e.g., `PROMPT="${PROMPT//\"/\\\"}"`) is fragile and we've already shipped two compound bugs in this hook (Pass 2 broken, session_id parse). Untestable in isolation; you can't import it from a test file.
- **Fix shape:** move the Python logic to `src/mem_fusion/hooks/prompt_inject.py` (a real importable module); shell wrapper becomes `exec $VENV/python -m mem_fusion.hooks.prompt_inject`. The stdin-parse + Pass-1 + Pass-2 logic gets unit tests.
- **Cost:** ~half a day per hook; ~2 days total. Pays for itself the next time we touch one.

**H4. `Connector` ABC is too thin for production trajectory.**
Today: `format_envelope(envelope) -> str` + `parse_envelope(body) -> Envelope | None`. Missing for production push/pull:
  - `verify_integrity(envelope)` — substrate may have its own integrity scheme (per C1)
  - `build_envelope_from_record(record, connector_id)` — needed by push (per C2)
  - `validate_config(config_entry)` — connector.json schema validation; per gap G3
  - `max_body_size` — substrate ceiling (Slack 40KB, GDrive ~100MB)
  - `supports_vector_in_envelope` — booleans for capability gating
- **Fix shape:** expand the ABC. Each new method is small; the discipline is naming them well and writing the SlackConnector implementations.
- **Cost:** ~half a day for the ABC expansion + Slack impl + tests.

### MEDIUM — tech debt, scope-creep risk

**M1. No shared test infrastructure.** Some tests use `tests/lib/harness.py` (Constellation tests), some import `core` directly, some are heredocs that pollute the production store and clean up after themselves. A shared `mock_slack.py` for connector tests, and an isolated-Qdrant fixture for storage tests, would let new contributors write tests without reinventing setup.

**M2. `build_filter` accumulates positional kwargs.** Already at 5 (`project`, `type_`, `since`, `min_importance`, `connector_id`). Will grow. Replace with a fluent builder or query object.

**M3. No unified config layer.** Four config files in three formats:
- `qdrant-config.yaml` (YAML)
- `constellation/config.json` (JSON)
- `connector.json` (JSON) — read by skill, no schema
- `connector_cursors.json` (JSON) — runtime state, mixed with config conceptually
Each gets parsed ad hoc. A `mem_fusion.config` module with per-file loaders and Pydantic-style validation would catch malformed configs at load time (G3).

**M4. Versioning scattered.** `VERSION = "0.4.0-alpha"` in `constellation.py`; mem-fusion has no `__version__`. A top-level `__version__` would let the wire envelope's `envelope_version` actually mean something.

### LOW — cosmetic

**L1.** Inconsistent docstring depth (some multi-page, some one-liners).
**L2.** A few `log.info` calls have format strings that always materialize even when log level filters them.
**L3.** Type annotations partial — many functions return `dict` (should be `TypedDict`s).

### Expanded Connector interface

```python
from typing import TypedDict
from abc import ABC, abstractmethod

class Envelope(TypedDict, total=False):
    envelope_version: int          # required: 1
    content:          str          # required
    content_hash:     str          # required; substrate-specific format
    origin_node:      str          # required
    submitted_at:     str          # required: ISO-8601 UTC
    type:             str
    tags:             list[str]
    project:          str
    importance:       int
    connector_ids:    list[str]
    groups:           list[str]    # legacy v0.4, optional
    vector:           list[float]  # optional: substrate may transmit
    # connector-specific extension fields allowed; receivers ignore unknown.

class Connector(ABC):
    """Wire-format adapter for a productivity-tool substrate."""

    type: str = ""

    # ── Wire format adapter ─────────────────────────────────────────
    @abstractmethod
    def format_envelope(self, envelope: Envelope) -> str: ...

    @abstractmethod
    def parse_envelope(self, body: str) -> Envelope | None: ...

    # ── Production helpers ──────────────────────────────────────────
    @abstractmethod
    def build_envelope_from_record(self, record: dict, connector_id: str) -> Envelope:
        """Build a wire envelope from a local stored memory record (output of core.export_record)."""

    @abstractmethod
    def verify_integrity(self, envelope: Envelope) -> tuple[bool, str | None]:
        """Substrate-specific integrity check. Returns (ok, reason)."""

    @abstractmethod
    def validate_config(self, config_entry: dict) -> list[str]:
        """Validate a connector.json entry. Returns list of errors; empty = ok."""

    # ── Capability metadata ─────────────────────────────────────────
    @property
    @abstractmethod
    def max_body_size(self) -> int:
        """Max body size in bytes for this substrate."""

    @property
    def supports_vector_in_envelope(self) -> bool:
        return True  # default; substrates with tight body limits may override
```

## Practical sequencing

Stage refactors so v0.5 ships clean and v0.6 inherits a healthier substrate. **Don't big-bang.**

### Stage 1 — ships with v0.5 (this week, ~1 day)

Critical-only. Minimum to make 0.5.0-016 push orchestration testable.

- C1: move integrity check into `Connector.verify_integrity`; `store_memory_from_envelope` accepts a connector arg.
- C2: add `Connector.build_envelope_from_record`; SlackConnector implements.
- C3: `Envelope` TypedDict in `connectors/envelope.py`; update producers + consumers.
- E2E test rewritten to call production helpers (real store_memory → real build_envelope_from_record → real format_envelope → mock Slack body → real parse_envelope → real store_memory_from_envelope).
- 0.5.0-015 content_hash canonical lands (architect-acked); use it consistently across wire + local.

### Stage 2 — v0.5.x maintainability pass (~1-2 weeks)

After 016 + 017 ship and we know the connector surface stabilizes.

- H1: split `core.py` into `core/` submodules.
- H2: split `constellation.py` into `constellation/` submodules.
- H3: hooks moved to Python modules; bash wrappers become thin exec'ers.
- H4: expand `Connector` ABC with `validate_config`, `max_body_size`, `supports_vector_in_envelope`.
- M1: shared test infrastructure (`mock_slack.py`, isolated-Qdrant fixture).

### Stage 3 — v0.6 substrate bump (alongside about_me identity work)

- Full `mem_fusion/` package layout (currently flat `src/`).
- M3: unified config layer with Pydantic schemas.
- M4: centralized `__version__`.
- Replace `build_filter` positional args with a builder (M2).
- Possibly add a second connector (gdrive or teams) as the forcing function for the Connector interface to harden.

## Decisions needed before I refactor

1. **Stage 1 scope ack** — is the "C1+C2+C3 + rewritten e2e test + 0.5.0-015" bundle the right "ship this week" target? I propose committing it before 0.5.0-016 push orchestration (which will consume the new helpers cleanly).
2. **Naming on the new Connector method.** I lean `build_envelope_from_record(record, connector_id)` but open to `record_to_envelope`, `format_record`, etc.
3. **Should `Envelope` be `TypedDict` (lightweight, dict-compatible, runtime accepts any dict) or `dataclass` (stricter, requires construction via class)?** I lean TypedDict for transition friendliness; can migrate to dataclass later if we want hard typing.
4. **Stage 2 timing.** Land before 0.5.0-016 + 017 to give them a cleaner platform, or after to avoid blocking? My read: AFTER, because the push/pull orchestration will tell us whether the current interface needs more methods. Don't pre-optimize the abstraction.

## Anti-pattern self-check (for me)

The user correctly diagnosed I'd been hacking together one-off scripts instead of producing maintainable code. Going forward principles I'm holding to:

- **Test the production function**, not a parallel scaffold. If a function doesn't exist yet, write it as production code first, then have the test call it.
- **No hand-edited data in tests** that production wouldn't edit. The moment I'm tempted to strip a field for "readability," I'm at a fork: either omit the field in production (with receive-side implications) or include it in the test. Never diverge.
- **Maintainability check before each commit:** would a fresh reader understand what production behavior this proves? If "no," it's the wrong test.
- **Don't grow `core.py`.** If a new responsibility lands, it gets its own module from day one.
- **Connector additions land via the ABC**, not via duplicated code paths.
