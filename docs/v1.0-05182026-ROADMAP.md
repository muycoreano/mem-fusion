## TL;DR

Mem-Fusion is on a deliberate arc from **peer mesh** (v0.3) → **consent-routed sharing** (v0.4) → **production-grade connectors** (v0.5) → **cross-machine identity** (v0.6) → **benchmarked public launch** (v0.7). Every release widens the same architectural commitment: local-first by default, sharing only when the user names a destination, identity preserved end-to-end. The four-property white-space (local · mesh · consent · identity) is the moat we're building toward; v0.7 is when that moat goes public with benchmark numbers and a real launch surface.

## Released

### v0.1.0 — Initial public release *(2026-05-08)*

The local foundation. Everything in v0.3+ builds on this substrate.

- **8 MCP tools:** `store_memory`, `search_memory`, `search_recent`, `upsert_memory`, `find_or_create`, `delete_memory`, `get_related`, `memory_stats`.
- **4 Claude Code hooks:** `SessionStart`, `UserPromptSubmit`, `Stop`, `PostToolUse(Write)`. Auto-capture and auto-recall, no taxonomy to design.
- **`/remember` skill** for high-importance user-curated stores.
- **AI-native install** — paste `INSTALL_MEM_FUSION.md` into Claude Code; Claude reads it and runs the install with your approval.
- **Stack:** Qdrant 1.13.4 + Ollama 0.20.5 + `nomic-embed-text` (768-dim), all local. No telemetry, no cloud, no SaaS lock-in.
- **macOS launchd integration** for Qdrant and Ollama.

[`CHANGELOG.md § [0.1.0]`](../CHANGELOG.md) for the full list.

### v0.3.0 — Constellation lands *(2026-05-12)*

Peer mesh. The first time mem-fusion crosses a machine boundary.

- **Two-daemon architecture:** Mem-Fusion stays stdio (per-session); Constellation runs as a persistent HTTP daemon (`com.branchapp.memfusion.constellation`).
- **9th MCP tool:** `export_record(id)` — returns a memory's full record incl. its 768-dim vector, so peers can faithfully receive without re-embedding.
- **Constellation surface:** `/memory/put`, `/memory/get`, `/peers`, `/peers/self`. Content-hash integrity verified at destination; per-group dedup; provenance chain preserved.
- **Mesh topology:** every Constellation peer is symmetric. No hub, no orchestrator. "Orchestrating" is a per-group role, not a node type.
- **Single Qdrant collection model:** mem-fusion and Constellation share `cowork_memories`; federation entries distinguished by payload tags. Simpler than disjoint collections; makes future upgrades a no-op on storage.

Design docs: [`CONSTELLATION_ARCHITECTURE.md`](CONSTELLATION_ARCHITECTURE.md), [`V0.3.0-PROJECT-PLAN.md`](V0.3.0-PROJECT-PLAN.md).

### v0.3.1 — LTS fork *(2026-05-13)*

Maintenance tag. The `v0.3.x` branch becomes the long-term-support line for users who don't track `main`. Future bug fixes against the v0.3 routing model land there.

## In flight

### v0.4 — The privacy invariant *(on `main`, pre-release)*

Replaces v0.3's content-classification routing with **explicit group-keyed sharing.** Every memory carries `groups: list[str]`; sharing happens only when the user names a destination. The default is `["personal"]` — local-only.

**Why it matters:** v0.3 had a content classifier that guessed what was safe to share. Any misclassification on the wrong side was a privacy leak. v0.4 makes consent the routing primitive — and that's an architectural invariant, not a policy. Mem0's *State of Agent Memory 2026* names privacy and consent as the unsolved problem in agent memory. v0.4 is the answer.

- **`groups: list[str]` field** on every memory, indexed for fast filtering.
- **Two new MCP tools:** `group_push(group, memory_ids?)`, `group_pull(group?)`.
- **`add_groups(memory_ids, groups)`** for store-now-share-later flows. Additive only — once memory propagates to a group, it can't be silently un-shared.
- **Push-time group filter:** the sender intersects each memory's `groups` with the receiver's membership. Receivers never see groups they aren't part of.

164 of 164 test invariants pass. Design doc: [`v0.4_MEMORY_ARCHITECTURE.md`](v0.4_MEMORY_ARCHITECTURE.md).

### v0.5 — Connectors + production-grade *(on `v0.5` branch, pre-release)*

The architectural pivot: Constellation becomes one of *several* ways to share, not the only one. **Connectors** bridge mem-fusion into productivity tools your team already uses — Slack first; GDrive, Teams, Notion, and custom adapters land on the same `Connector` ABC.

**Stage 1 complete and production-validated** (2026-05-18, end-to-end against a real Slack channel):

- **`src/connectors/` package** — `Connector` ABC with `format_envelope` / `parse_envelope` / `verify_integrity` / `build_envelope_from_record`. `SlackConnector` is the reference implementation.
- **Substrate-agnostic ingest** — `core.store_memory_from_envelope` handles loopback prevention, integrity verification, dedup, vector resolution (use embedded vector if present, else re-embed), and Qdrant upsert. Connectors are pure wire-format adapters.
- **Canonical content_hash** — `sha256(NFC(text).encode("utf-8")).hexdigest()` — full 64-char, no truncation, Unicode-normalized. Migration script handles existing memories idempotently.
- **`/remember push <connector-id>` + `/remember pull <connector-id>` skill orchestration** — explicit connector naming; no bare push.
- **G11 receive-side filter** keeps smoke-test scaffolding out of production stores.
- **Cursor persistence** per connector at `~/.local/share/mem-fusion/connector_cursors.json`.
- **`install.sh`** — replaces the paste-into-Claude install flow for users who want a conventional shell installer. Self-bootstrapping, single file.

In flight: hook Pythonification (Stage 1.5 of refactor), the broader `src/mem_fusion/` package layout (Stage 3).

Design docs: [`v0.5_CONNECTOR_ARCHITECTURE.md`](v0.5_CONNECTOR_ARCHITECTURE.md), [`v0.5_CONTENT_HASH_SPEC.md`](v0.5_CONTENT_HASH_SPEC.md), [`v0.5_FIRST_PULL_SEMANTICS.md`](v0.5_FIRST_PULL_SEMANTICS.md), [`v0.5_INSTALL_FLOW.md`](v0.5_INSTALL_FLOW.md), [`v0.5_STAFF_AUDIT_2026-05-18.md`](v0.5_STAFF_AUDIT_2026-05-18.md).

## In design

### v0.6 — Cross-machine identity

Every memory remembers whose perspective it came from. Across machines, across sessions, across teammates.

**Why it matters:** Mem0's "actor-aware" attribution is in-session only. v0.6's `about_me` is the cross-machine, cross-session equivalent — and it's the foundation for organization-scale memory fusion. When a memory propagates through three peers, the question *"who originated this?"* should still have a clear answer.

- **`about_me` schema** on every memory — role, machine, identity attribution.
- **Schema bump** — v0.5's payload format extends to carry identity context.
- **Hook lifecycle** picks up the identity at write time; sync protocol preserves it end-to-end.
- **The substrate change** bundles chunked-embedding payload fields (`canonical_id`, `chunk_index`, `chunk_count`) into the same schema bump — amortizes one substrate change instead of two.

Design doc: [`v0.6_NODE_IDENTITY_CONTEXT.md`](v0.6_NODE_IDENTITY_CONTEXT.md).

### v0.7 — Gap-anchored public launch

Nine work packages organized by what they close. The frame: **where do competitors' users hurt, and which hurts do we already win on, which can we close in v0.7, and which do we share honestly?**

**Group 1 — Credibility (must ship):**

- **WP-1 Benchmark suite + public dashboard** — LOCOMO + LongMemEval + a multi-machine benchmark of our own design. Methodology public from day one. No published numbers = no "best memory layer" claim.
- **WP-2 Install matrix + OSS readiness** — CI matrix across macOS Intel/ARM, Linux Ubuntu/Fedora. Apache-2.0 license. `CONTRIBUTING.md` codifies the engineering principles from the v0.5 staff audit.
- **WP-3 Positioning content + README rewrite** — leads with the four-property intersection; cites Mem0's *State of Agent Memory 2026* as *"they named the open problem; here's the architecture answering it."* Mutually elevating, never adversarial.

**Group 2 — New capabilities (must ship):**

- **WP-4 Typed knowledge graph (native, NO Neo4j)** — auto-extracted typed edges (`works_at`, `supersedes`, `complements`, `blocks`, `decides`, `related_to`) as Qdrant payload arrays. Pattern-match where possible (zero LLM cost), LLM-augment only on confidence threshold.
- **WP-5 Consolidation pass (proposal-only, no auto-mutation)** — async periodic process detects stale memories, dead wikilinks, redundant content. Surfaces findings as proposal memories the user reviews. Preserves our corrective-memory immutability — the architectural difference from comparable consolidation features elsewhere.
- **WP-6 Memory-as-work-queue formalization** — structured `action_item` and `bug_report` memory types with `assignee`, `status`, `blocks`, `resolves` and a real state machine. Builds on v0.6 identity.

**Group 3 — Ecosystem (CRITICAL but can split to v0.8 if scope balloons):**

- **WP-7 OpenClaw integration adapter** — mem-fusion plugs into OpenClaw as a memory layer. Distribution channel, not competition.
- **WP-8 Framework SDK adapters** — LangChain, LlamaIndex, AutoGen. Top 3 cover the long tail.
- **WP-9 Connector breadth: Notion + GitHub** — two new connectors beyond Slack; demonstrates the model generalizes.

Design doc: [`v0.7_ROADMAP_DRAFT.md`](v0.7_ROADMAP_DRAFT.md). PM measurement plan: [`v0.7_PM_MEASUREMENT_PLAN.md`](v0.7_PM_MEASUREMENT_PLAN.md).

## What we are not building

Decisions, not open questions. Calling them out so this roadmap doesn't drift into a wishlist:

- **Cloud SaaS offering.** Local-first is the moat; a hosted plane would erode it.
- **OS-style memory tiering.** Different design philosophy. We have one Qdrant collection by deliberate choice.
- **All 21 framework SDKs.** Top 3 cover the long tail; the rest is marketing copy.
- **Multi-user SaaS coordination.** Personal mesh + team-scoped connectors is the model.
- **Web UI / dashboard.** CLI + Claude Code MCP is the interface. Revisit in v0.9+ if the community asks.
- **Implicit pattern learning.** Comparable products have this; we don't. Acknowledged honestly; not a roadmap item.

## Updating this file

Each material release lands a CHANGELOG entry; this roadmap gets refreshed when:
- A version moves from *in flight* → *released*, or
- A version moves from *in design* → *in flight*, or
- A work-package's scope shifts materially.

**Revision convention:** each material update lands as a **new file** under `docs/v<N>-<MMDDYYYY>-ROADMAP.md`. Examples:
- `v1.0-05182026-ROADMAP.md` (this file)
- `v1.1-05252026-ROADMAP.md` (a refinement that doesn't change the overall shape)
- `v2.0-06152026-ROADMAP.md` (a material re-shape — e.g. v0.6 ships and we add v0.8 in-design)

Minor-version bumps (`v1.0 → v1.1`) for refinements; major-version bumps (`v1.x → v2.0`) for re-shapes. Prior revisions stay in the repo as the visible historical record. The latest file is canonical; older files are read-only history. When in doubt, link to the latest in any external reference.
