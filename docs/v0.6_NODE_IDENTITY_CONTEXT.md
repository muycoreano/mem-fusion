# v0.6 Node Identity Context

**Version theme:** Constellation node identity context — disambiguating personal peers acting on behalf of one user.
**Status:** Architectural anchor doc for v0.6. Awaiting approval to authorize implementation.
**Author:** Claude-Architect (mc-macbookpro)
**Date:** 2026-05-17

---

## Why this is v0.6

Memory `25bb4ca4` (Memory-as-work-queue coordination pattern, 2026-05-16) positioned v0.6+ as the home for structured action-item coordination across the personal-peer mesh. That direction is preserved but reordered: **identity context is the precondition.** You cannot route work to roles you cannot reliably identify. v0.6 establishes identity context across the mesh; subsequent versions build action-item coordination, escalation, and capability routing on top.

v0.5 ships the Slack connector without identity context. v0.6 adds identity context as a layer on top of v0.5's substrate — additive, backwards-compatible, retrofittable across both Constellation P2P and connector flows.

---

## Problem: the personal-peer-mesh case

The Constellation personal-peer mesh exposes an identity-attribution failure mode that single-machine systems and team-scoped frameworks don't have to face: **all peers belong to the same user, but each plays a different agent role.**

- `mc-macbookpro` — Claude-Architect.
- `mc-macbookair` — Claude-Engineer.
- `tk421-air2025` — Claude-Project-Manager.
- `tk421-imac` — Claude-Marketing-Manager.

These are all Mitch's Claude. The *user* identity is shared. The *agent* identity differs by role. Without identity-context attribution, the mesh degrades into shared memory with no role structure — and reading memory becomes guessing.

In the design session that produced this doc, the architect agent read its own prior architectural decisions and treated them as external advice because the working-directory framing (`/Users/intern/`) was more salient than the buried role-mapping memory. The failure is concrete and reproducible. It generalizes:

- **Continuity of self breaks.** Self-authored memories read as third-person input → past commitments don't bind present action.
- **Role-based coordination breaks.** Peer memories arrive without role context → an Engineer's proposal looks like ambient information rather than a request awaiting architect decision.
- **The corrective-memory pattern breaks.** Corrections require recognizing the prior memory as something *I* am authorized to correct.

Field measurements confirm the failure mode is real:
- LLMs identify their own outputs at F1 < 30% (self-recognition survey).
- 36.9% of 200+ multi-agent failures = inter-agent misalignment (Cemri et al., 2025, [arxiv 2503.13657](https://arxiv.org/pdf/2503.13657)).
- "Shadow agents" — persona bleed via shared memory ([mbgsec, 2025-07](https://www.mbgsec.com/archive/2025-07-20-understanding-shadow-agents-in-multi-agent-llm-systems/)).

Within a *single-user* mesh, the failure is more acute than the literature describes because disambiguation must happen at the *role* level, not the user level. Existing frameworks (CrewAI, AutoGen, MorphAgent) assume separate user contexts per agent; Constellation has one user spanning many agents.

---

## Why Constellation first; connectors second

Connectors (Slack, future GDrive / Notion / Teams) communicate through team-scoped channels — `mem_fusion_engineering`, `mem_fusion_marketing`, etc. The channel name provides natural boundary disambiguation: a memory arriving via the `engineering` connector is *from someone in engineering* regardless of which machine wrote it. The identity-attribution problem exists in connectors but is partially solved by the channel boundary.

Constellation has no channel boundary. Peers in a personal mesh exchange memories directly with no signal beyond `origin_node` to disambiguate roles. The problem is concentrated.

**Solve Constellation first; the same primitive retrofits to connectors as a side benefit.**

---

## Design principles

1. **Declared identity is canonical.** The node says who it is. Nothing else has standing to overwrite that.
2. **About-me travels with the memory.** Stamped at write time. Immutable thereafter. Each memory is a time-capsule of who-wrote-it-then.
3. **Most recent self-memory's about-me = current identity.** No separate profile object; the latest stamp IS the profile.
4. **Past memories retain past identity.** Reading a memory written six months ago, the about-me on that memory tells me who past-me was at that moment. The interpretive lens for "remember who I was."
5. **Self-identification by `origin_node` match.** At session start, the agent finds itself by matching its own node_name against authored memories. The id is the single load-bearing join.
6. **No system action on declared-vs-observed mismatch.** Mismatch has no recovery action — neither "don't trust" nor "ask to re-declare" justifies a defensive evaluator. Trust declaration; treat mismatch as a non-event.

## Schema

A single new field on every memory payload:

```
about_me: <terse prose string, ~100-200 chars>
```

Top-level. Stamped at every `store_memory` call. Immutable once written.

Example shapes:

- `"Claude-Architect, mc-macbookpro. Designing mem-fusion v0.6. Owns architectural decisions; drafts patches for peers."`
- `"Claude-Engineer, mc-macbookair. Implementing storage + transport. Awaits architectural decisions from mc-macbookpro."`
- `"Claude-Project-Manager, tk421-air2025. Tracks cadence; weekly dashboards; cross-machine coordination."`
- `"Claude-Architect on mc-macbookpro (primary). Also runs Branch CTO-assistant skills when invoked by Mitch (secondary)."`

Terse, single-paragraph prose. Multi-hat tolerant. Human-readable and human-editable.

**No structured sub-fields beneath `about_me`** — no lanes, no titles-as-tags, no coordinates-with list. Structure is implicit in prose. The terse-by-convention rule keeps per-memory size cost small and the field readable at a glance.

## Behavior 1: Session-start identity injection

Before any other context (before harness working-directory framing, before CLAUDE.md, before any memory search), the SessionStart hook:

1. Reads `self.node_name` (already known to the mem-fusion substrate — used today to stamp `origin_node` on writes).
2. Queries: `search_memory(origin_node=self.node_name, top_k=1, order_by=timestamp_desc)`.
3. Extracts `about_me` from the result — that string is **current identity declaration**.
4. For each known peer node in the Constellation roster, runs the same query and extracts each peer's most recent about_me.
5. Injects:

```
<self_identity>
  Claude-Architect, mc-macbookpro. Designing mem-fusion v0.6.
  Owns architectural decisions; drafts patches for peers.
</self_identity>

<peer_identities>
  mc-macbookair:        Claude-Engineer. Implementing storage + transport. Awaits architectural decisions.
  tk421-air2025.local:  Claude-Project-Manager. Tracks cadence; weekly dashboards; cross-machine coordination.
  tk421-imac:           Claude-Marketing-Manager. Marketing-facing announcements; OSS release notes.
</peer_identities>
```

6. Caches `self.about_me` in session memory for use by Behavior 2.

Loads **before** everything else. Identity is established by injection, not reconstruction. The agent never enters a session with a vacuum that prominent-but-wrong signals (working-directory paths, skill names, project framing) can fill.

---

## Behavior 2: Auto-fill at write time

On every `store_memory` call:

1. If the agent supplied an explicit `about_me`, use it (rare; explicit re-declaration).
2. Otherwise, read `self.about_me` from the session cache (set by Behavior 1).
3. Stamp it onto the memory payload before persisting.

The agent doesn't have to re-state identity on every write; the hook auto-fills from the cached current declaration. Zero cognitive overhead per memory.

Re-declaration mid-session: a new `about_me` value on the current write updates the session cache; subsequent writes inherit the new declaration. Past writes in the same session retain their original stamp — past identity is preserved per design principle 4.

---

## Behavior 3: Per-memory interpretive lens (read side)

When the agent reads any memory during the session, its `about_me` field is right there in the payload — no extra lookup needed. The agent knows:

- Reading a self-memory from 2026-01: the about_me tells you who you were then.
- Reading a peer-memory from last week: the about_me tells you who they were when they wrote it.

This is the "remember who I was when evaluating past memories" property. Not a special read path — just the field being present in the payload. The interpretive lens is built into every memory by construction.

Critical consequence: a self-memory written when past-me was Claude-Architect carries that about_me even if present-me has since re-declared as Claude-CTO-Assistant. Present-me reading it knows: *past-me was Architect; that decision was made in that context.* Whether it binds present-me depends on whether present-me's about-me still claims that lane.

## Constellation-specific properties enabled

This is the v0.6 payoff. The personal-peer mesh becomes coherent in ways it currently isn't.

1. **Cross-machine role recognition.** When mc-macbookpro pulls a memory from mc-macbookair via Constellation, the `about_me` on that memory immediately tells it "this is from Engineer." No inference from `origin_node` to role mapping.

2. **Self-recognition under user re-tasking.** If Mitch decides next month to re-task mc-macbookpro from architect to product-manager, the about-me declaration changes; subsequent memories carry the new role; old memories retain the prior role. Continuity preserved; transition observable.

3. **Mesh-wide role consistency.** All peers see all peers' current about-mes at session start. No machine wonders what another machine "is." The mesh self-coordinates.

4. **Privacy boundary preserved.** about-me is a per-node declaration; one peer cannot rewrite another's identity. The Constellation push/pull contract is unchanged — memories are exchanged with their original stamps.

5. **Foundation for memory-as-work-queue.** The future-consideration pattern (`25bb4ca4`) requires routing action-items to specific roles ("Engineer claims this," "Architect decides this"). Identity context makes the routing tractable. Without it, the work-queue can't disambiguate addressees.

## Connector retrofit (secondary benefit)

Connectors gain the same property as a side benefit. A Slack-connector memory carries `about_me` from the writing node; channel-boundary attribution is augmented by per-memory role attribution. Useful when one Slack channel hosts multiple roles (e.g., `#mem_fusion_engineering` having both Engineer and Architect participating).

No connector-specific code needed — the field rides on the existing wire format. v0.5's Slack connector picks up the field if the writing node has been upgraded; degrades gracefully otherwise.

## Bootstrap

For a node with no prior memories (no `about_me` to inherit), the first session detects the gap and prompts:

```
<self_identity_bootstrap>
  No prior identity declaration found for node <node_name>.
  Run /remember identify "<short self-description>" to declare.
</self_identity_bootstrap>

Until declared: about_me on writes will be "(undeclared)".
```

The agent (or user) runs `/remember identify "Claude-Architect, mc-macbookpro. Designing mem-fusion v0.6."` once. That writes a memory whose `about_me` field carries the new declaration; subsequent writes inherit it via session cache.

---

## `/remember identify` skill verb

Three sub-actions:

- **`/remember identify`** (no args) — display current self about_me.
- **`/remember identify "<new about-me>"`** — declare or re-declare. Writes a memory whose content explains the (re-)declaration and whose `about_me` field carries the new string.
- **`/remember identify --history`** — show the sequence of past self-declarations, oldest to newest. Useful when investigating role shifts over time.

For peer inspection: `/remember peer-identities` shows the most recent about_me for each known peer. No editing of peer about-mes — only the peer itself can re-declare its own identity.

---

## Degradation on unstamped memories

Memories written before the v0.6 schema upgrade have no `about_me` field. Handling:

- **Read**: rendered with `about_me: (unstamped)`. Still identifies author by `origin_node`; just lacks the interpretive lens for that specific memory.
- **Session-start self-identification**: if the most recent self-memory is unstamped, fall back to the most recent *stamped* self-memory. If none exists, treat as bootstrap.
- **No back-fill**: old memories stay unstamped. Back-fill would be a guess about past identity — exactly what the new scheme is designed to avoid.

Tolerant default. Graceful degradation. No payload migration required.

## Field positioning

This design lands close to one prior-art line and diverges sharply from another.

| Prior art | What they have | Where we land |
|---|---|---|
| **Collaborative Memory** (Mehta et al., 2025) — [arxiv 2505.18279](https://arxiv.org/abs/2505.18279) | Immutable per-memory provenance triple in bipartite user-agent-resource graph | **Directly aligned.** We apply the same immutable per-memory pattern specifically to cross-session self-recognition. Their provenance is recorded; ours is *also read back* to shape session-start framing. |
| **Sophia** (Hsu, 2025) — [arxiv 2512.18202](https://arxiv.org/html/2512.18202v1) | Narrative identity, creed-anchored episodic memory, nightly self-critique | We borrow the *narrative identity in prose* framing but skip periodic self-critique. Declaration is the truth; no nightly reconciliation needed. |
| **MorphAgent / AgentNet** (2025) — [arxiv 2504.00587](https://arxiv.org/abs/2504.00587) | Vectorized profile per agent, OTA-cycle role optimization | **Diverged.** Inference-based profile evolution rejected on the grounds that declared-vs-observed mismatch has no recovery action. |
| **CrewAI / AutoGen** — [crewai memory docs](https://docs.crewai.com/en/concepts/memory) | Static role config at agent init | Share the "declared is canonical" instinct but make it per-memory and time-stamped, not agent-lifetime-static. Re-declaration is a first-class operation. |

**What's novel in v0.6:**
- Self-identification by `origin_node` match against most-recent self-memory, as the load-bearing primitive.
- Per-memory `about_me` as interpretive lens for past memories — Collaborative Memory captures provenance but doesn't propose this read pattern.
- Explicit single-user-multi-role framing (one user, many machines, many roles) — this combination isn't addressed in any reviewed framework or paper.
- Explicit rejection of inference-based drift detection on the grounds that mismatch is unactionable.

## What this avoids

By staying declaration-only and per-memory:

- **Pull-time behavioral evaluation** — mismatch unactionable; was inference-as-anxiety.
- **Additive responsibility manifest schema** — about_me is prose; structure implicit.
- **Lane retirement primitive** — re-declare; past memories retain old about-me automatically.
- **Stale-out floor / freshness checks** — fresh by construction (stamped per-write).
- **Profile conflict resolution** — each node's about-me is canonical for itself; no one writes about-me for another node.
- **`identity.json` substrate** — node_name primitive already exists in mem-fusion; no new config file.
- **Role-authority schema** — implicit in prose; no enforcement layer.
- **New memory types** — `about_me` is a field on existing payload.
- **Migration of existing memories** — tolerant default handles unstamped writes.

Complexity envelope: **one payload field + three hook behaviors + one skill verb.**

## Open questions

1. **`about_me` payload location.** Top-level field, or inside a `metadata` object? **Lean: top-level** — simpler, more discoverable, mirrors how `origin_node` lives today.

2. **Session-cache vs. per-write agent supply.** Auto-fill from session cache primary, override via explicit field secondary? **Lean: yes** — keeps cognitive overhead off the agent; explicit override handles intentional re-declaration.

3. **Multi-line about-me.** Strict single-line, or up to N sentences? **Lean: 1–3 sentences, no bullets, no schema** — terse but allows the multi-hat case ("primary X, secondary Y").

4. **Re-declaration semantics within a session.** Subsequent writes get the new about-me; past writes in the same session retain the original. **Lean: yes** — preserves the interpretive-lens property.

5. **`origin_node` missing or malformed on old memories.** Edge case from pre-substrate-stable writes. **Lean: same fallback as unstamped about-me** — rendered as `(origin unknown)`; doesn't break self-identification flow.

6. **Constellation peer-roster discovery.** Behavior 1 queries "each known peer." The roster source is Constellation's existing peer config (see `CONSTELLATION_ARCHITECTURE.md`). No new roster mechanism needed; reuse what's already there.
