## 1. The audience question — "best" depends on whose job we're winning

The agent-memory category has three distinct jobs-to-be-done. Each competitor wins a different one:

| Competitor | Job they win | User they win |
|---|---|---|
| **Mem0** | "I'm building an agent and need a memory layer fast, plus a hosted plane if I don't want to operate one." | Agent-framework integrators, SDK-heavy stacks, hosted-OK |
| **gbrain** | "I want a personal second-brain with knowledge graph + LLM augmentation." | Solo knowledge-workers, note-takers, single-operator |
| **Letta** | "I'm studying agent memory architectures — give me OS-like tiering." | Research-flavored, academic, framework-purist |

Mem-fusion's job is none of those. Ours is:

> **My AI assistant gets sharper at *my* work, in *my* codebase, with *my* preferences — across sessions, across my machines, with sharing that means something when I opt in.**

### Audience laddering

Win one audience first. Adjacent audiences extend out from there:

```
WIN FIRST (v0.7 launch target)
└─ Claude Code power devs
   acute pain: session amnesia + lost context between days
   trust posture: local-first matters; corporate-EDR-aware
   reachable distribution: same Slack channels, GitHub repos, HN/dev.to readership

WIN NEXT (v0.7 + 6 months)
└─ Privacy-conscious dev teams (corporate, EDR-locked, small startups)
   acute pain: "we tried Mem0 but it phones home with broken opt-out"
   landing path: WP-3 README rewrite + Mem0 quote-and-cite blog

WIN LATER (v0.8 → v1.0)
└─ Agent-framework integrators (the Mem0 audience proper)
   acute pain: SDK breadth + bring-your-own-framework
   landing path: WP-8 LangChain / LlamaIndex / AutoGen adapters

WIN STRATEGIC (v1.0+)
└─ Organizational AI backbone — teams, then orgs
   acute pain: "AI knowledge trapped in individuals"
   landing path: WP-6 memory-as-work-queue + WP-9 GitHub / Notion connectors
```

**Decision: target Claude Code power devs as the v0.7 launch primary audience.** Trying to win all four at v0.7 wins none. Their channels are our reachable distribution, their pain is most acute, and their trust posture aligns with our architectural facts.

## 2. Four axes of "best" in agent memory

Quality reduces to four measurable axes. Different competitors win different axes. The winner of the category wins more than one and is honest about the rest.

| Axis | What it measures | Where mem-fusion stands today |
|---|---|---|
| **1. Retrieval quality** | Does the right memory surface when needed? Precision/recall over multi-session and long-context tasks. | No public benchmark today. Internal observation: usable, hook-driven recall fires reliably on score > 0.75 threshold. WP-1 closes the public-proof gap. |
| **2. Latency** | p50 / p95 / p99 for store, search, sync. Embed-to-searchable freshness. | Strong: ~30-80ms store, 10-25ms search locally. Team-scale sync via the Slack connector is sub-second per message. Mem0's Neo4j p99 ~46.9s is what we beat by not using Neo4j. |
| **3. Robustness** | Install success rate. Data integrity over time. Push/pull error rate at team scale. | Improving. Cold-start fix landed v0.5; install matrix coverage is WP-2 scope. Internal install runs are clean post-fix; need external evidence. |
| **4. Trust / Privacy** | Telemetry surface. Data egress posture. Consent model clarity. Audit trail. | **Won by architectural fact.** Zero telemetry. Local-by-default. Group-keyed-by-explicit-intent consent. Mem0's broken opt-out is an enterprise disqualifier we are built to beat. |

We win axis 4 outright today; we are competitive on axis 2; we have no public proof on axis 1; we have weak public proof on axis 3. **WP-1 + WP-2 are the credibility bridge to a v0.7 public launch.** Without them, "best" is unsupportable.

## 3. The proof stack — five proof types compose

A benchmark number alone does not win a category. Five proof types compose; we need all of them stacked, not any one perfectly:

```
1. BENCHMARK PROOF      LOCOMO, LongMemEval, multi-machine bench (we lead by definition).
                        Methodology code public from day one.
                        External reviewer pre-publication.
                        → WP-1 in v0.7 roadmap.

2. ARCHITECTURAL PROOF  Four-property intersection table.
                        Six-architectural-wins table (see §4 below).
                        Mem0 quote-and-cite: "they named the problem; we built the answer."
                        → WP-3 in v0.7 roadmap.

3. SOCIAL PROOF         External testimonials, GitHub stars, conference acceptances,
                        media mentions. Stars are vanity unless paired with retention
                        and contribution; we measure both.

4. ADOPTION PROOF       Install completion rate, connector ecosystem breadth,
                        community PRs. Real users + real contributions = product-market
                        fit signal. Measured via opt-in surveys (no telemetry).

5. QUALITY-OVER-TIME    Public CHANGELOG cadence (already maintained).
                        Bug-to-fix lead time (already low; verifiable in git history).
                        Test count trajectory (171 → 202 and growing).
                        Public weekly dashboard (already live in docs/status/).
```

Each proof type compensates for weaknesses in others. Benchmark a hair behind Mem0? Architectural proof carries the story. Star count a fraction of theirs? Quality-over-time + adoption trajectory shows the curve.

## 7. Resolving the no-telemetry tension

There is a real tension: "we don't track users" is a launch pillar (v0.7 commitment #1) AND we need to measure user experience improvement. Two mechanisms resolve it:

### 7.1 `mf metrics` opt-in CLI / skill

A local CLI command (and Claude-Code skill counterpart) that emits a structured anonymized report the user voluntarily shares.

**Shape (proposal):**

```
$ mf metrics
mem-fusion v0.7.0
───────────────────────────────────────
Installed:           34 days ago
Memory store:        342 memories (212 personal, 84 engineering, 46 product)
Connectors:          2 declared (slack: engineering, slack: personal-devices)
Last 7d activity:    47 stores, 312 searches, 8 pushes, 12 pulls
Storage:             18.3 MB Qdrant data
Embedding latency:   p50 28ms, p95 71ms, p99 98ms
Search latency:      p50 11ms, p95 24ms, p99 38ms
Hook injection rate: 0.34 memories/prompt (of prompts where any memory injected)
Cold-start status:   OK
───────────────────────────────────────
Share this report:  mf metrics --share          (posts to your GitHub issue / Slack of choice)
Show full schema:   mf metrics --schema
Privacy notes:      mf metrics --privacy
```

Zero passive collection. The user runs the command, the user shares the output. Anonymized by default (no paths, no project names, no memory content — just counts and latencies).

### 7.2 Voluntary lifecycle surveys

Prompt at install: *"Want to help mem-fusion improve? Run `mf metrics --share` in 7 days. Anonymized; you see exactly what gets sent."*

Cadence: post-install (day 0), 7-day-post-install, 30-day-post-install, then quarterly. Bounce rate is fine — signal-to-noise on voluntary opt-in beats passive telemetry every time.

### 7.3 Why this becomes its own positioning artifact

"We measure user experience without tracking users" is a story worth telling. WP-3 positioning content can include this. **It is the privacy-invariant pattern applied to product measurement itself** — the architectural-fact win on axis 4 extends to how we run the product, not just how the product runs.
