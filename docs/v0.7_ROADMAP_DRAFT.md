## Why this rewrite

The previous draft listed nine features arranged into three pretty tracks. That's not a roadmap; that's a wishlist. The gaps research changed the inputs: I now have **twelve specifically-voiced user pains** across Mem0 and gbrain, each citable to a GitHub issue, HN thread, or independent review. Every line of work in v0.7 should answer one of those pains, exploit one of them, or honestly close one of our own.

The frame shifts from *"what should we build?"* to *"where do their users hurt, and which hurts do we already win on, which can we close in v0.7, and which do we share?"*

---

## The five commitments driving this roadmap

From the gaps analysis. These are not bullets to debate — they are the decisions I'm making and asking my PM and Marketing hats to operate against. Pushback is welcome on *how* we execute; the *what* is locked.

1. **"No telemetry, no beacon, local-first" becomes a v0.7 launch pillar.** Mem0's PostHog-on-by-default with broken opt-out (M2) is an enterprise disqualifier. We win this by architectural accident. Stop hiding the win.
2. **Corrective-memory immutability is our answer to junk-extraction.** Mem0's 97.8% production junk rate (M1) is a structural failure of LLM-extract-then-trust. Our pattern (memories immutable; corrections supersede) is the structural answer. Name it in positioning.
3. **Published benchmarks are non-negotiable for v0.7 ship.** We have NONE today. Without numbers, "best memory storage and sharing system" is unsupportable. Clean LOCOMO + LongMemEval + a multi-machine bench of our own design.
4. **WP-4 typed-edge graph must NOT pick up Neo4j.** Mem0's Neo4j latency cliff (M7, p99 ~46.9s) and orphan-on-delete (mem0#3245) are our spec inputs. Native edges on Qdrant payloads + wikilinks; no separate graph DB.
5. **Install path gets matrix testing.** gbrain's weekly install-wedge complaints (G1, G4) are the brittleness we will not inherit. v0.5/v0.6/v0.7 ship through `src/scripts/fixes/0.5.0-NNN-*.sh` discipline; v0.7 extends that to public install-path matrix coverage.

Everything below executes against these five. If a WP doesn't trace to one of them (or to an honest gap we share), it doesn't belong in v0.7.

## Where we already win — and what positioning has to do

The most important strategic finding from the gaps research: we beat both competitors today on their highest-volume complaint surfaces, by architectural accident. Positioning's job in v0.7 is to **make those wins visible without sounding adversarial**.

| Their pain (cited) | Our win (architectural fact) |
|---|---|
| M1 — 97.8% production junk audit | Corrective-memory pattern: memories immutable; corrections supersede. Explicit `/remember` for high-importance; hook-captured low-stakes with clear write controls. |
| M2 — Telemetry on, opt-out broken | No PostHog, no beacon, no telemetry path. Local-first by design. |
| M5 — OSS self-host is second-class | Self-hosted *is* the product. No hosted plane to back-fall to. |
| M6 — No auth, CORS wide open | No HTTP server to leave open. Local MCP surface, run as the user. |
| G2 — Hardcoded OpenAI embeddings under "your brain on your machine" marketing | We actually run Ollama + nomic-embed-text locally. The claim is provably true. |
| G3 — Single-operator scope | Personal mesh (Constellation) + connectors model. Two cleanly separated axes that gbrain explicitly skipped. |

These are not "we'll catch up." They're "we've been right about this since v0.4." Positioning content (WP-3 below) leads with these, framed as principled architectural choices — not attacks.

## Workpackages — re-ordered by gap-closure value

Nine WPs. Three groups by commitment level. Each WP names the gap reference (M# or G#) it closes or the strategic commit (#1–5) it serves.

### Group 1 — Close our own credibility / honesty gaps (must ship in v0.7)

**WP-1 — Benchmark suite + public dashboard.**
*Closes:* commitment #3 (benchmark credibility). Closes Mem0 M3 (LOCOMO integrity scandal — their methodology was wrong; ours will be transparent and independently runnable).
*Scope:* LOCOMO + LongMemEval + a novel multi-machine coordination benchmark of our own design (which we automatically lead because no competitor runs in that mode).
*Methodology constraint:* benchmark privately first; if results are worse than competitors on a given dimension, fix before publishing. Methodology code public from day one.

**WP-2 — Install matrix + OSS readiness pass.**
*Closes:* commitment #5 (install brittleness defense). Pre-empts gbrain G1/G4 pattern. Closes our own install/setup risk-class.
*Scope:* CI matrix (macOS Intel/ARM, Linux Ubuntu/Fedora, Bun/Node, Ollama-running/Ollama-missing) for the install flow. License choice (Apache-2.0). CONTRIBUTING.md, security policy, hardened install, comprehensive README.
*Ownership:* PM-hat-led; engineer-hat hardens install; architect-hat reviews license.

**WP-3 — Positioning content + README rewrite.**
*Closes:* commitments #1 (no-telemetry pillar) + #2 (corrective-memory as junk answer). Surfaces M2/M5/M6 + G2/G3 wins we already have.
*Scope:* README rewrite leading with the four-property intersection (local-first + P2P mesh + role-attributed identity + group-keyed sharing). Blog post citing Mem0's State of Agent Memory 2026 as "they named the open problem; here's the architecture answering it" — mutually elevating tone, not adversarial. Conference talk submission (HN-adjacent venues; possibly Strange Loop or LocalLLaMA showcase). All content blocks on WP-1 benchmark numbers for credibility scaffolding.
*Ownership:* Marketing-hat-led; architect-hat reviews framing.

### Group 2 — Build new capabilities that exploit competitor gaps (must ship in v0.7)

**WP-4 — Typed knowledge graph (native, NO Neo4j).**
*Closes:* commitment #4. Closes Mem0 M7 (Neo4j p99 ~46.9s + orphan-on-delete). Closes gbrain feature parity (their typed-edge story is one of the most-cited reasons users pick them).
*Scope:* Auto-extracted typed edges (`works_at`, `supersedes`, `complements`, `blocks`, `decides`, `related_to`) as Qdrant payload arrays; pattern-match where possible (zero LLM cost), LLM-augment only on confidence threshold. Integrates with our existing wikilink convention.
*Non-functional requirement:* no separate graph database. No Neo4j. No FalkorDB. Edges live in payload; queries traverse via existing search infrastructure. This is the architectural decision; the spec serves it.

**WP-5 — Consolidation pass (proposal-only, no auto-mutation).**
*Closes:* gbrain feature parity (their Dream Cycle is the second-most-cited feature). Closes nothing user-cited — *defensive feature parity*. Preserves our differentiator (corrective-memory immutability) by making consolidation propose, not mutate.
*Scope:* Async periodic process. Detects stale memories, dead wikilinks, redundant content. Surfaces findings as proposal memories the user reviews. NEVER auto-mutates. This is the architectural difference from gbrain's Dream Cycle — and the difference is the moat.

**WP-6 — Memory-as-work-queue formalization.**
*Closes:* extends our unique lead (memory `25bb4ca4` — observed-emerging in v0.5). No competitor has anything analogous.
*Scope:* Structured `action_item` and `bug_report` memory types with `assignee`, `status`, `blocks`, `resolves` fields and a state machine (open → in_progress → resolved). Foundation for "mem-fusion turns your machines into a coordinated team" as a shipped feature, not an emergent property.
*Depends on:* v0.6 about_me identity context shipping (role assignment requires reliable role attribution).

### Group 3 — Ecosystem expansion (CRITICAL but partially deferrable to v0.8 if scope balloons)

**WP-7 — OpenClaw integration adapter.**
*Closes:* gbrain G3+G7 from a different angle — distribution play, not direct gap-close. OpenClaw is a host that needs a memory layer (per competitive analysis); we plug in.
*Scope:* Mem-fusion exposes its MCP surface to OpenClaw's tool router; alternatively, a thin OpenClaw adapter maps `MEMORY.md` operations to mem-fusion `store_memory` calls.
*Risk:* OpenClaw was ~5 weeks old at competitive-analysis time. Pin to tagged version; track but don't promise.

**WP-8 — Framework SDK adapters (LangChain, LlamaIndex, AutoGen).**
*Closes:* Mem0's integration-breadth advantage (their 21 SDKs). Top 3 cover the long tail; the other 18 are marketing copy.
*Scope:* Thin per-framework shims over the MCP surface; ~200-400 LOC each. Reuse benchmark harness from WP-1 for adapter QA.

**WP-9 — Connector breadth: Notion + GitHub.**
*Closes:* gbrain G3 (single-operator) by demonstrating the connector model generalizes; closes gbrain G7 (narrow integration). GitHub specifically pairs with WP-6 work-queue for end-to-end issue-to-resolution flow.
*Scope:* Two new connector types beyond Slack. Notion for team docs/wiki; GitHub for issue/PR coordination.

## What we are NOT doing in v0.7

These are decisions, not open questions. Calling them out so PM and Marketing review doesn't reopen settled scope:

- **Cloud SaaS offering.** Off-strategy per gaps research. Mem0's hosted plane lures users back from their broken OSS path (M5); we don't have one and don't want one. Local-first is the position.
- **OS-style memory tiering (Letta's pattern).** Speculative value; no user-cited pain.
- **All 21 framework SDKs.** Top 3 cover the long tail. The rest is marketing copy.
- **Multi-user SaaS coordination.** Personal mesh + team-scoped connectors is the model.
- **Web UI / dashboard.** CLI + Claude Code MCP is the interface. Revisit in v0.9+ if community asks.
- **Implicit pattern learning.** Mem0's M4 — they have it; we share it; honest acknowledgment, not a roadmap item. Different product.

## Open questions for my PM and Marketing hats

Genuine unknowns the WPs will need to resolve. Naming them so per-WP design doesn't lose them.

1. **WP-1 methodology fairness.** Benchmarking competitors while building our own invites bias accusations (we just cited Mem0 for doing exactly this). External runner or independent reviewer pre-publication? Marketing should weigh in on perception risk.
2. **WP-3 tone calibration on the "Mem0 named the problem" blog.** Mutually elevating, not adversarial — but the line is real. Marketing owns this call.
3. **WP-4 extraction-confidence threshold.** Pattern-match-first hybrid still needs an LLM-fallback gate. Where? Architect-hat to spec; engineer-hat to validate.
4. **WP-5 consolidation aggressiveness.** Too many proposals = spam (the exact risk we cite in Mem0 M1). Too few = invisible. Tunability surface is unclear.
5. **WP-7 OpenClaw API stability.** Verify before scoping. If their API moves fast (v0.x cadence), pin or wait.
